1. PROJECT OVERVIEW & EXECUTIVE SUMMARY
================================================================================

Continuous-track Unmanned Ground Vehicles (UGVs) operate in unstructured, harsh 
off-road environments (dense tall grass, rocky terrain, ditches, and slopes). 
Unlike wheeled platforms, tracked vehicles can climb steps up to 15 cm and crush 
deformable vegetation up to 40 cm without losing traction.

However, navigation fails when robots cannot distinguish between:
  * Traversable Features: Small debris (<= 15 cm), deformable grass, flat dirt trails.
  * Lethal Hazards: Rigid boulders (> 15 cm), drop-offs/ditches, and steep inclines (> 35°).

This project implements a real-time, edge-optimized Perception Pipeline that 
fuses Stereo RGB-D Depth Geometry with Semantic Scene Understanding to output:
  1. Real-time 3D Object Detection & Range Localization (X, Y, Z, Azimuth Bearing).
  2. Actionable Traversability Classification (RUN-OVER ALLOWED vs LETHAL AVOID).
  3. 2.5D Local Grid Costmaps (nav_msgs/OccupancyGrid) for local path planners.
  4. Global OpenMap / OpenStreetMap (OSM) topo-metric waypoint routing.

3. WHY PURE 2D DEEP LEARNING (E.G. YOLO) FAILS ON TRACKED ROBOTS
================================================================================

Many robotics teams make the critical mistake of using standard 2D object 
detectors (like YOLOv8) for off-road navigation. Here is why pure 2D fails:

1. THE 2D BOUNDING BOX TRAP:
   A standard 2D detector detects a "rock" in the camera frame, but has ZERO 
   awareness of real-world metric height. It cannot tell whether the rock is 
   8 cm high (which continuous tracks easily crawl over) or 28 cm high (which 
   will high-center the chassis and flip the vehicle).

2. THE PURE DEPTH / LIDAR BLINDSPOT:
   Raw point clouds or depth sensors detect a 25 cm height profile, but have 
   ZERO material awareness. They treat 25 cm of soft, crushable grass identically 
   to a 25 cm solid concrete curb, forcing the robot to take unnecessary 
   detours around harmless weeds.

3. OUR HYBRID FUSION SOLUTION:
   * Deep Learning identifies material properties (Soil, Grass, Rock, Water/Ditch).
   * 3D Depth Geometry computes exact physical clearance:
       delta_h = Z_robot(u, v) - Z_ground(X_r, Y_r)
   * The Physics Engine evaluates delta_h against tracked vehicle thresholds.

4. CORE PERCEPTION MODULES & MATHEMATICAL FORMULATIONS
================================================================================

--------------------------------------------------------------------------------
4.1 CAMERA GEOMETRY & VECTORIZED 3D BACK-PROJECTION (camera.py)
--------------------------------------------------------------------------------
Coordinate Frames:
  * Camera Optical Frame: +X Right, +Y Down, +Z Forward (optical axis).
  * Robot Base Frame (base_link): +X Forward, +Y Left, +Z Up (Ground = Z=0).

Mathematical Projection:
For each pixel (u, v) with optical depth Z:
  X_c = ((u - c_x) * Z) / f_x
  Y_c = ((v - c_y) * Z) / f_y
  Z_c = Z

Transformation to Robot Base Frame:
  P_robot = R_cam_to_base * P_cam + t_cam_to_base

Optimization:
The unit ray directions in the robot frame are precomputed during initialization.
At runtime, 3D back-projection is executed in a single vectorized NumPy operation:
  P_robot = Depth * Ray_Dir_Robot + t_cam_to_base
Execution Latency: < 1.0 ms for full 640x480 resolution.

--------------------------------------------------------------------------------
4.2 VECTORIZED RANSAC GROUND PLANE FITTING (geometry.py)
--------------------------------------------------------------------------------
The local ground surface directly in front of the vehicle is modeled as a plane:
  a*X + b*Y + c*Z + d = 0, where ||(a, b, c)|| = 1 and c > 0 (normal points up).

Fast Vectorized Batch RANSAC:
  1. Generates 80 candidate triplet sample planes in parallel.
  2. Computes candidate normal vectors via cross-product: N = (p2-p1) x (p3-p1).
  3. Evaluates all residuals simultaneously in matrix form:
       Residuals = |Sample_Points @ N.T + d|
  4. Selects the plane maximizing inlier count within distance threshold (4 cm).
  5. Computes ground surface slope angle:
       theta_slope = arccos(c)
Execution Latency: ~7.0 ms on edge CPU.

--------------------------------------------------------------------------------
4.3 SEMANTIC SEGMENTATION & 4-CLASS OFF-ROAD TAXONOMY (taxonomy.py, segmenter.py)
--------------------------------------------------------------------------------
Functional 4-Class Taxonomy:
  * Class 0 (FREE_DRIVABLE): Flat soil, dirt trails, gravel roads, packed earth.
  * Class 1 (SOFT_TRAVERSABLE): Tall grass, light weeds, brush (crushable by tracks).
  * Class 2 (RIGID_OBSTACLE): Rocks, boulders, tree trunks, concrete barriers.
  * Class 3 (NEGATIVE_HAZARD): Ditches, trenches, drop-offs, cliffs, water bodies.

Supported Backbones:
  * PIDNet-S (Proportional-Integral-Derivative Network for real-time edge vision).
  * MobileNetV4-SegFormer.
  * Multi-spectral FeatureSegmenter (HSV color + Laplacian texture + depth edges).

--------------------------------------------------------------------------------
4.4 PHYSICS-INFORMED TRAVERSABILITY ENGINE (decision_engine.py, vehicle_profile.py)
--------------------------------------------------------------------------------
Vehicle Physics Envelope:
  * Chassis Belly Clearance (H_clearance): 10 cm (0.10 m)
  * Track Step Climb Limit (H_step_max): 15 cm (0.15 m)
  * Maximum Safe Step-Down (H_drop_max): 12 cm (0.12 m)
  * Soft Vegetation Crush Limit (H_soft_max): 40 cm (0.40 m)
  * Maximum Incline Limit (theta_max): 35.0 degrees

Decision Classification Rules:
  * RULE 1 (Negative Ditch Hazard):
      IF delta_h < -12 cm OR SemanticClass == NEGATIVE_HAZARD
      THEN -> NEGATIVE HAZARD (Cost: 255 - Fatal Stop/Avoid)

  * RULE 2 (Lethal Rigid Obstacle):
      IF delta_h > 15 cm (Step Climb Limit)
      THEN -> LETHAL OBSTACLE (Cost: 254 - Avoidance Corridor Required)

  * RULE 3 (Traversable Rigid Step / Debris):
      IF 3 cm < delta_h <= 15 cm AND SemanticClass == RIGID_OBSTACLE
      THEN -> RUN-OVER ALLOWED (Cost: 25 to 80 - Safe Track Crawl)

  * RULE 4 (Soft Vegetation Override):
      IF delta_h <= 40 cm AND SemanticClass == SOFT_TRAVERSABLE
      THEN -> RUN-OVER ALLOWED (Cost: 15 - Friction penalty, but safe to drive)

  * RULE 5 (Steep Terrain Hazard):
      IF Ground_Slope > 35 degrees
      THEN -> INCLINE HAZARD (Cost: 254 - Rollover Risk)

--------------------------------------------------------------------------------
4.5 2.5D LOCAL GRID COSTMAP WITH TRACK FOOTPRINT INFLATION (costmap.py)
--------------------------------------------------------------------------------
Grid Specifications:
  * Size: 8.0 m x 8.0 m centered around robot (X: -1.0 m to +7.0 m, Y: -4.0 m to +4.0 m).
  * Resolution: 5 cm / cell (160 x 160 grid).
  * Vectorized Accumulation: Uses NumPy ufunc (np.maximum.at) for sub-2ms aggregation.
  * Morphological Inflation: Dilates lethal cells (Cost >= 254) by track safety radius 
    (35 cm) to guarantee safe clearance margins for Nav2 trajectory planners.

--------------------------------------------------------------------------------
4.6 3D SPATIAL OBSTACLE EXTRACTION & METRIC LOCALIZATION (obstacle_detector.py)
--------------------------------------------------------------------------------
Extracts discrete 3D spatial clusters and computes:
  * 3D Centroid: (X_c, Y_c, Z_c) in meters from robot base_link.
  * Radial Ground Range: d = sqrt(X_c^2 + Y_c^2) meters.
  * Horizontal Azimuth Bearing: phi = arctan2(Y_c, X_c) degrees.
  * Obstacle Dimensions: Length (X), Width (Y), Height above ground (delta_h).
  * Action Tag: is_run_over_allowed (True/False).

--------------------------------------------------------------------------------
4.7 ROS2 / NAV2 BRIDGE & OUTPUT FORMATS (ros2_bridge.py)
--------------------------------------------------------------------------------
Publishes native ROS2 message payloads:
  * /perception/traversability_grid: nav_msgs/msg/OccupancyGrid (160x160, int8 [-1..100]).
  * /perception/detected_obstacles: vision_msgs/msg/Detection3DArray.
  * /perception/telemetry_json: Full JSON diagnostic summary.

5. OPENMAP & GLOBAL TOPO-METRIC NAVIGATION INTEGRATION
================================================================================

How this Perception Engine integrates with OpenMap / OpenStreetMap (OSM):

1. HIERARCHICAL DUAL-LAYER NAVIGATION:
   * Global Layer (OpenMap / OSM): Supplies topological trail networks, GPS waypoints 
     spaced 20m - 100m apart, and satellite elevation priors.
   * Local Layer (Our Perception Engine): Operates as the real-time ego-centric 
     shield (0 - 10m) detecting dynamic obstacles, fallen rocks, and ditches 
     not recorded on satellite maps.

2. GEO-REFERENCING THE 2.5D COSTMAP:
   Every local costmap grid cell (X_r, Y_r) is transformed into global WGS-84 
   coordinates via robot GNSS/INS odometry:
     [Latitude, Longitude].T = T_base_to_GPS * [X_r, Y_r].T
   This allows local traversability discoveries to update the global OSM trail graph.

3. OPEN-VOCABULARY 3D VISION-LANGUAGE GROUNDING:
   Using OpenMap / CLIP embeddings, natural language instructions from operators 
   (e.g., "Follow the dirt path, avoid the boulder on the right and the ditch") 
   are mapped directly onto our 3D traversability costmap.

9. RECOMMENDED SEARCH & PATH PLANNING ALGORITHMS
================================================================================

For a continuous-track UGV operating in unstructured off-road environments,
navigation requires a hierarchical dual-layer search and planning architecture:

+------------------------------------------------------------------------------+
| GLOBAL SEARCH LAYER (OpenMap / OSM Topological Graph, 20m - 2km)             |
| Algorithm: Weighted A* / Hierarchical Multi-Resolution D* Lite              |
| Input: OpenStreetMap GPS trail waypoints, satellite elevation contours       |
+--------------------------------------+---------------------------------------+
                                       | Global Waypoint Sub-Goals
                                       v
+------------------------------------------------------------------------------+
| LOCAL SEARCH & TRAJECTORY LAYER (Our 2.5D Perception Costmap, 0 - 8m)        |
| Algorithms: Hybrid A* (Kinodynamic Search) + MPPI / TEB Controller           |
| Input: 2.5D Traversability Costmap, 3D Obstacle Heights, Skid Kinematics     |
+------------------------------------------------------------------------------+

1. LOCAL PATH SEARCH: HYBRID A* (KINODYNAMIC SEARCH)
   * Why Standard Grid A* Fails: Standard 2D grid A* searches discrete (X, Y) 
     cells without vehicle orientation (theta), turning resistance, or vehicle 
     momentum. A path that zig-zags on a grid causes continuous tracks to 
     repeatedly skid-steer and lose traction in soil or mud.
   * Why Hybrid A* is Ideal: Searches continuous state space (x, y, theta) by 
     projecting kinematically feasible motion primitives (forward arc, reverse, 
     pivot in place) matching the continuous-track skid-steer geometry.
   * Cost Function Integration: Direct fusion with our 2.5D Costmap:
       Total_Cost = Path_Length + w_terrain * Costmap(x, y) + w_steer * delta_theta + w_h * delta_h

2. REAL-TIME DYNAMIC REPLANNING: D* LITE (DYNAMIC A*)
   * In off-road navigation, hazards appear dynamically (e.g. stereo camera 
     discovers a 20 cm trench or a fallen rock at 3.5 m).
   * Standard A* must re-plan the entire search tree from scratch (15 - 40 ms).
   * D* Lite maintains the search graph and only updates nodes affected by the 
     new obstacle, replanning optimal avoidance paths in < 2.0 ms.

3. REAL-TIME TRAJECTORY TRACKING: MPPI (MODEL PREDICTIVE PATH INTEGRAL)
   * Runs directly on the onboard GPU to evaluate 2,000 - 4,000 parallel 
     candidate speed/steering rollouts [v, omega] every 20 ms.
   * Evaluates rollouts against our 2.5D Costmap and track slip friction models, 
     sending smooth velocity commands (cmd_vel) to the track motor controllers.
